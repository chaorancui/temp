# 编译器

# 编译期静态内存规划

核心范式归纳
"凡是计算图能静态分析 + 硬件受限"的场景，都会走到这条路：

1. 编译期生成内存布局（编译器决定谁占哪个 buffer）
2. 运行时只传偏移（无 malloc、零开销）
3. 内存池复用（生命周期不重叠的张量挤同一块 buffer）

甚至：业界凡是做"边缘端推理引擎"的，几乎都用了你这套东西的某种变体——区别只在术语和实现细节，不在原理。

**一、为什么可以这样**

根本原因是编译期静态内存规划
这种场景 GPU/NPU 跑任务时，所有张量生命周期是已知的（哪个算子先跑、哪个算子输出给谁），所以编译器可以做这件事：

- 把生命周期不重叠的张量塞进同一块 buffer 的不同 offset
- 把多个 buffer 拼成一个全局内存池

好处对硬件至关重要：

| 好处       | 解释                                                                              |
| ---------- | --------------------------------------------------------------------------------- |
| 零 malloc  | 某些 GPU/NPU 上没有 libc/OS，所有内存在模型加载时一次分配完毕，运行时只有指针传递 |
| 可预测时延 | 没有内存碎片导致的随机性，适合实时推理                                            |
| 省内存     | 一个 buffer 复用给多个张量（生命周期不重叠），峰值内存大幅下降                    |
| 硬件友好   | 算子参数只用一个偏移就能定位张量，不需要查名字                                    |

**二、业界什么领域也用同样的东西**

这套「编译期静态内存规划 + 运行时按偏移引用」不是 GPU/NPU 特有，是任何「无 OS / 受限内存 / 实时性 / 算子调度」运行时的通用范式。规范术语叫：

- Static Memory Planning / Memory Planning — ML 编译器圈
- Arena Allocation / Memory Arena — 通用系统
- Buffer Scheduling / Static Buffer Allocation — DSP/嵌入式
- Memory Pool with Offset Addressing — 通用描述

同类系统对照表

| 领域             | 系统                               | 用同样的东西（术语）                                                    |
| ---------------- | ---------------------------------- | ----------------------------------------------------------------------- |
| ML 编译器        | TVM                                | storage_align, storage_rewrite pass；Buffer 抽象；arena-based workspace |
| ML 编译器        | XLA (TensorFlow)                   | HeapSimulator、BufferAssignment、OrderedBasicBlock                      |
| ML 编译器        | MLIR (memref + BufferDeallocation) | memref 的 offset/strides；AllocationScope                               |
| ML 编译器        | Glow (Meta/Facebook)               | Tensor 引用 Allocation，MemoryAllocator 线性分配 + 复用                 |
| ML 编译器        | ONNX Runtime 内部                  | MemPattern、MemoryPlanner、slab/arena                                   |
| ML 编译器        | TensorFlow Lite                    | MicroAllocator、MemoryPlanner (Greedy/BufferPlan)                       |
| ML 编译器        | MNN (阿里)                         | BufferAllocator + Group 池化 + 偏移引用                                 |
| GPU              | CUDA Graphs                        | kernel argument 是 device pointer（偏移于预先分配的 pool）              |
| GPU              | CUDA Graphs                        | Vulkan push constants descriptor 偏移于预先绑定的 buffer                |
| DSP / 嵌入式 GPU | Qualcomm Hexagon, CEVA, Cadence    | Tensilica buffer descriptor + offset，所有内存在 init 时分定            |
| DSP 音频框架     | Android Audio HAL / Tinyalsa       | circular buffer slot preallocation, ring buffer                         |
| ISP / Camera     | 高通 Camx、华为 ISP                | buffer pool + slot index 流转                                           |
| 实时系统         | AUTOSAR (汽车)、ROS 2 (内存管理)   | pre-allocated memory pool + offset addressing                           |
| 游戏引擎         | Unity Job System / Burst           | NativeArray 引用预先分配的 chunk + offset                               |
| 图像处理库       | OpenCV Mat ROI                     | Mat 共享底层 MatAllocator 的 buffer + offset/stride                     |
| 数据库           | PostgreSQL                         | shared buffers、LMDB page pool + offset addressing                      |
